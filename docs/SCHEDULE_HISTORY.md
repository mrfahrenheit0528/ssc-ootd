# Apply weekly assignments to earlier semester dates

Imported visits already appear in Analytics as visits and recorded hours. They
count as voluntary if the saved schedule for that date has no required officers.
The scheduling upgrade created an initial revision and retained earlier dates;
later ordinary saves therefore did not replace those historical assignments.

## Install the upgrade once

If the initial, dashboard refinement and CSV import migrations already ran:

1. Open [202611140001_schedule_history.sql](../supabase/migrations/202611140001_schedule_history.sql).
2. Copy the entire file into a new query in Supabase's SQL Editor and run it once.
3. Refresh the updated dashboard. No reader configuration changes are needed.

Do not rerun the earlier SQL files. For a new empty project, run all four
migrations in filename order. Installing this upgrade alone does not change
historical assignments or attendance; applying the schedule is an admin action.

## Apply your existing first-semester schedule

1. Open **Day Config**, choose the semester, then **Weekly recurring assignments**.
2. Click **Edit schedule**. Keep the existing officer checkboxes as they are.
3. Set **Apply schedule to > Whole semester (including earlier dates)**.
4. Open **Calendar day types** to preview the earlier dates if desired.
5. Click **Save changes**. This works even if no checkboxes changed.
6. Open **Analytics**, choose the same semester and date range, then
   **Refresh report** or **Analyze attendance**. Do not re-import the CSV.

For a semester's first admin-configured schedule, Whole semester is preselected.
For subsequent routine edits, Today and future dates is preselected so prior
reports retain their saved assignments. You can explicitly choose Whole semester
to correct historical setup later. The schedule stays locked until Edit schedule
is chosen, and Cancel restores its saved assignments and application scope.

## What changes

Whole semester assigns the new weekly revision to calendar dates inside the
selected term, including historical revisions and any future pinned revisions.
Untouched empty lists generated by the legacy migration become inherited weekly
assignments. Deliberately saved custom lists (including empty lists), No Classes,
Optional and calendar notes remain intact. Saving an individual date makes its
officer list explicit even if its values are unchanged.

Attendance IDs, names, timestamps, imports, photos and roster profiles are not
rewritten. Earlier schedule revisions remain stored; the new revision records
its application scope, creator and creation time. Archived semesters remain
read-only; reactivate the intended term before changing its schedule.

Analytics recalculates required attendance from these date assignments. A visit
on an officer's required day becomes assigned attendance; other visits remain
voluntary. No Classes and Optional still have no required absences. Required
dates without a recorded clock-in count as absent once finalized at 9 PM, so
applying a schedule across a long period does not imply 100% fulfillment.
